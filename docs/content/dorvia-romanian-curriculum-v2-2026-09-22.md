# DORVIA Romanian — برنامه‌ی آموزشی نسخه‌ی ۲ (۲۲ سپتامبر ۲۰۲۶)

**جایگزین نسخه‌ی ۱** (`dorvia-romanian-curriculum-v1-2026-09-20`). آن سند بر
پنج «مرحله» بنا شده بود که از حوزه‌ها عبور می‌کردند؛ این سند بر **هفته‌های
حوزه‌ای** بنا شده است. آنچه از نسخه‌ی ۱ زنده می‌ماند در بخش ۷ آمده.

---

## ۱. واحد طراحی: هفته، نه روز

یک حوزه در یک هفته **کامل** دیده می‌شود: واژگانش، افعالش، مکالمه‌هایش، موقعیت‌های
واقعی‌اش. یک هفته بانک، یک هفته فرودگاه، یک هفته فروشگاه.

دلیلش فنی است نه سلیقه‌ای: چیزهایی که در یک میدان معنایی هستند همدیگر را نگه
می‌دارند. چهل واژه‌ی بانکی که با هم دیده شوند بهتر می‌مانند تا چهل واژه‌ی پراکنده
از ده حوزه. و «این هفته از پس بانک برمی‌آیم» یک هدف تمام‌شدنی است.

عدد «روزی پنج واژه» **نتیجه** است نه قاعده: حوزه‌ی چهل‌واژه‌ای تقسیم بر هفت روز
می‌شود حدود شش تا در روز.

---

## ۲. هفته‌ی صفر — پیش‌نیاز همه

سی عبارت بقا (`dorvia-romanian-stage0-content-v1-2026-09-21`) حوزه نیستند؛
پیش‌نیازند. کسی که نمی‌تواند بگوید «رومانیایی بلد نیستم» نمی‌تواند وارد هفته‌ی
بانک شود. این محتوا از قبل ساخته و منتشر شده است.

---

## ۳. ترتیب حوزه‌ها از خط زمانی خودِ آدم می‌آید

| هفته | حوزه | چرا اینجا |
|---|---|---|
| ۰ | بقا | پیش‌نیاز |
| ۱ | فرودگاه و ورود | اولین جایی که واقعاً آنجاست |
| ۲ | خرید روزانه | اولین نیاز روز دوم |
| ۳ | حمل‌ونقل شهری | جابه‌جایی روزمره |
| ۴ | بانک | معمولاً هفته‌ی اول تا دوم لازم می‌شود |
| ۵ | مسکن و قبوض | اجاره، مالک، آب و برق |
| ۶ | پزشک و داروخانه | اولین نیاز پیش‌بینی‌نشده |
| ۷ | اداری و اقامت | IGI، فرم‌ها، وقت اداری |
| ۸+ | **وابسته به شغل** | بیمارستان، دانشگاه، محل کار، جاده، حسابداری |
| بعد | رستوران، مال، پارک، همسایگی | زندگی اجتماعی |

**فرودگاه اول است نه چون مهم‌ترین است، چون اولین است.** کاربر تازه رسیده، خسته و
مضطرب، و هنوز هیچ چیز دیگری برایش اتفاق نیفتاده.

از هفته‌ی هشتم، ترتیب با شغل عوض می‌شود — همان شش شغلی که تأیید شد. پرستار زودتر
به بیمارستان می‌رسد، دانشجو زودتر به دانشگاه.

---

## ۴. حوزه‌ها هم‌اندازه نیستند

«یک هفته برای هر حوزه» واحد اسمی است، نه قانون. بانک شاید چهل واژه دارد و پارک
پانزده تا. هر حوزه `estimatedWeeks` خودش را اعلام کند (۰.۵، ۱، ۲) وگرنه یا
هفته‌ی پارک خالی می‌ماند یا هفته‌ی اداری فشرده و ناقص.

---

## ۵. بازیافت باید در داده باشد، نه در حافظه‌ی مؤلف

«?Cât costă» هم مال فروشگاه است، هم بانک، هم مال، هم تاکسی. اگر هفته‌ها جزیره
باشند، کاربر یک چیز را چهار بار از صفر یاد می‌گیرد.

راه‌حل: جمله‌ها به **شناسه‌ی واژه** وصل می‌شوند. آن‌وقت «این هفته چه واژه‌هایی از
هفته‌های قبل برمی‌گردند» یک محاسبه است، نه یک یادآوری. و مرور فاصله‌دار خودش از
همین گراف بیرون می‌آید.

---

## ۶. مدل داده — واژه و فعل موجودیت مستقل می‌شوند

### واژه

```ts
type RomanianWord = {
  id: string;                    // پایدار
  lemma: string;                 // 'cont bancar'
  pos: 'noun' | 'verb' | 'adj' | 'adv' | 'expression';
  gender?: 'm' | 'f' | 'n';      // برای اسم اجباری
  definiteForm?: string;         // 'contul bancar'
  plural?: string;               // 'conturi bancare'
  translations: { en: string; fa: string };
  domains: DomainId[];           // یک واژه می‌تواند چند حوزه داشته باشد
  source: PhraseSource;
  reviewer?: string | null;
  status: 'draft' | 'review' | 'published' | 'archived';
};
```

⚠️ **جنسیت و صورت معرفه برای اسم اختیاری نیستند.** رومانیایی حرف تعریف را به
انتهای اسم می‌چسباند (`cont` → `contul`). واژه‌نامه‌ای که این را ندهد، نصف
بی‌فایده است — کاربر می‌داند «حساب» یعنی `cont` ولی نمی‌تواند بگوید «آن حساب».

### فعل

```ts
type RomanianVerb = {
  id: string;
  infinitive: string;            // 'a deschide'
  translations: { en: string; fa: string };
  domains: DomainId[];
  conjugation: {
    prezent:    PersonSet;
    conjunctiv: PersonSet;       // să deschid …
    perfect:    PersonSet;       // am deschis …
    viitor:     PersonSet;
  };
  source: { label: string; url: string; retrievedAt: string };  // اجباری
  status: 'draft' | 'review' | 'published' | 'archived';
};

type PersonSet = {
  eu: string; tu: string; el: string;
  noi: string; voi: string; ei: string;
};
```

**چهار زمان، به این ترتیب:** حال ساده، **conjunctiv**، گذشته‌ی نقلی، آینده.

conjunctiv عمداً دوم است. در رومانیایی بدون `să` هیچ درخواستی ساخته نمی‌شود —
«vreau să deschid»، «pot să plătesc». این ساختار در سطح مبتدی اجتناب‌ناپذیر است
و تعویقش یعنی کاربر نمی‌تواند چیزی بخواهد.

**نکته‌ای که یک ردیف اضافه را حذف می‌کند:** `dumneavoastră` همان صورت `voi` را
می‌گیرد. پس جدول صرف از قبل صورت رسمی را دارد؛ فقط باید ردیف `voi` را با برچسب
«شما (رسمی)» نمایش داد، نه اینکه ردیف هفتمی بسازیم.

### تفکیک تولید و درک در ضمایر

سیاست رجیستر می‌گوید کاربر رسمی صحبت کند. پس:

| ضمیر | تمرین تولید | نمایش برای درک |
|---|---|---|
| eu, noi | ✓ | ✓ |
| voi (= dumneavoastră) | ✓ | ✓ |
| tu, el, ei | ✗ | ✓ |

یعنی `el deschide` را می‌فهمد ولی تمرینِ گفتنش نمی‌کند. همان تفکیکی که برای
`informalVariant` گذاشتیم.

### اتصال جمله به واژه

```ts
// روی RomanianPhrase
wordIds?: string[];
verbIds?: string[];
```

این تنها چیزی است که بازیافت را قابل محاسبه می‌کند.

## ۶-ب. قواعد اعتبارسنجی که از این مدل بیرون می‌آیند

پنج قاعده‌ی تازه، به سبک V1 تا V8 — سیاست به قید build تبدیل شود نه به انضباط:

| # | قاعده |
|---|---|
| V9 | هر `wordId`/`verbId` ارجاع‌شده در جمله باید وجود داشته باشد |
| V10 | هر فعل منتشرشده باید `source.url` داشته باشد — صرف استخراج می‌شود، تولید نمی‌شود |
| V11 | هر اسم منتشرشده باید `gender` و `definiteForm` داشته باشد |
| V12 | واژه نباید در حوزه‌ای دیرتر از جمله‌ای که از آن استفاده می‌کند معرفی شود |
| V13 | هر حوزه‌ی منتشرشده باید `estimatedWeeks` داشته باشد |

**V12 مهم‌ترینشان است** و فقط به‌خاطر اتصال ممکن شده: جلوی آموزش جمله‌ای را
می‌گیرد که واژه‌اش هنوز معرفی نشده. یعنی منطق خود برنامه‌ی آموزشی در زمان build
اجرا می‌شود.

## ۷. آنچه از نسخه‌ی ۱ دست‌نخورده می‌ماند

- جلسه‌ی روزانه‌ی ترکیبی: محتوای تازه + مرور + یک تمرین شنیداری. مرور ستون
  اقتصاد محصول است، نه قابلیت لوکس.
- سؤال چهارم پرسشنامه اندازه‌ی جلسه را تعیین می‌کند (۱۰/۲۰/۴۰ دقیقه).
- هیچ درسی قفل نمی‌شود؛ «برنامه‌ی امروز» و «پیشنهاد بعدی» جای قفل را می‌گیرند.
- پرسشنامه با تشویق، نه اجبار.
- اصل مفهومی: الگو و جای خالی، نه حفظ رشته. حالا با لایه‌ی واژه و فعل، این اصل
  زیرساخت واقعی دارد.
- بدون ادعای سطح CEFR.

## ۸. اثر بر نقشه‌ی تجاری

برآورد محتوا عوض می‌شود: دوازده حوزه‌ی کامل یعنی حدود **۵۰۰ تا ۶۰۰ واژه، ۱۰۰
فعل و ۲۵۰ جمله** — تقریباً سه تا چهار برابر برآورد قبلی (۱۷۵ عبارت).

در عوض چیزی می‌سازد که سه ماه محتوای پیوسته دارد، نه بیست‌وپنج روز. برای اشتراک
ماهانه این تفاوت بین «ماه دوم لغو می‌کند» و «ماه دوم تازه وسط کار است» است.

**آستانه‌ی روشن‌کردن پرداخت عوض می‌شود:** به‌جای «۱۰۵ عبارت»، معیار می‌شود
**شش تا هشت حوزه‌ی کامل** — حدود دو ماه محتوای پیوسته برای کسی که تازه مشترک
شده.

## ۹. حوزه‌ی اول: فرودگاه و ورود

اولین حوزه‌ای که کامل می‌شود. دو دلیل:

۱. اولین نیاز واقعی کاربر است.
۲. بیشتر واژگانش از تابلوها، فرم‌ها و متن‌های رسمی قابل **استخراج و ارجاع** است —
   `Sosiri`، `Plecări`، `Control pașapoarte`، `Vamă`، `Bagaje`. برای محتوایی که
   بازبین بومی ندارد، این مهم‌ترین مزیت ممکن است: منبع به‌جای تولید.

## ۱۰. موارد باز

۱. فهرست نهایی افعال هر حوزه.
۲. منبع مرجع صرف افعال (یک منبع، نه چند تا، تا یکدست بماند).
۳. اینکه مکالمه به‌عنوان موجودیت جدا لازم است یا زنجیره‌ای از جمله‌ها کافی است.
